### Projects Scene
> **요약:** JSON 데이터를 기반으로 사용자의 프로젝트 포트폴리오를 출력하는 씬입니다. 데이터 개수와 무관하게 한정된 UI 객체만을 재사용하여 리소스를 최적화하는 캐러셀(Carousel) 슬라이드 연출을 구현했습니다.

#### 주요 로직
* **순환형 캐러셀 슬라이드 알고리즘 (`ProjectsPrefabManager`):** * 화면에 보이는 3개의 카드와 화면 밖 좌우에 숨겨진 대기용 카드 2개, 총 5개의 UI 프리팹(`projectContainer`)만으로 구성된 슬라이더 풀(Pool)을 구축했습니다.
  * `DOTween` 및 `Cubic Ease-Out` 수학 공식을 결합하여, 단순히 이동만 하는 것이 아니라 약간의 텐션(`PunchRotation`)이 가미된 고급스러운 슬라이드 전환 애니메이션을 구현했습니다.
* **동적 메모리 최적화 및 이미지 캐싱 (`Dictionary Cache`):** * JSON에서 제공하는 URL/로컬 경로로 이미지를 비동기 로드할 때, `Dictionary<string, Texture2D>`를 활용한 캐싱 계층을 두어 한 번 다운로드한 이미지는 중복 통신 없이 즉시 불러오도록 최적화했습니다.
* **이벤트 기반 아키텍처 결합도 최소화 (`Action` Event):** * 개별 프로젝트 프리팹 클릭 시 상세 팝업을 띄우는 동작을 `Action` 델리게이트(`OnPrefabClicked`)로 브로드캐스팅하여, 데이터 패널과 UI 팝업 컨트롤러 간의 직접적인 참조(의존성)를 제거했습니다.

#### 트러블슈팅: 다량의 데이터 렌더링 부하 및 슬라이드 연속성 문제 해결
* **문제:** 서버나 로컬에서 받아온 프로젝트 데이터 개수만큼 UI 프리팹을 생성하면 메모리 낭비가 심해지며, 양옆에서 자연스럽게 대기하다가 밀려 들어오는 슬라이드 뷰를 끊김 없이 구현하는 데 물리적인 위치 계산 에러가 발생했습니다.
* **분석:** 단순히 배열 내 UI의 `anchoredPosition`을 이동시키는 것만으로는, 화면 밖으로 완전히 나간 프레임을 다시 반대편으로 가져와 새로운 데이터를 덮어씌우는 '무한 순환' 동작의 타이밍과 인덱싱을 동기화하기 어려웠습니다.
* **해결 (모듈러 연산을 활용한 논리적 인덱스 순환 구조 도입):**
  * 슬라이드 애니메이션이 종료되는 즉시(`FinalizeSlideMove`), `_uiHeadIndex = (_uiHeadIndex + direction + 5) % 5`라는 모듈러(나머지) 연산 공식을 적용하여 화면 밖으로 나간 객체를 수학적으로 반대편 대기열 위치로 즉각 스냅(Snap)시켰습니다.
  * 이와 동시에 이동된 빈 슬롯에 다음 순서의 JSON 데이터를 덮어씌우는(`Setup`) 로직을 결합하여, 실제로는 **단 5개의 오브젝트가 제자리걸음을 하고 있지만 사용자에게는 무한히 새로운 카드가 자연스럽게 밀려 들어오는 듯한 완벽한 착시 연출**을 적은 연산 비용으로 완성했습니다.
